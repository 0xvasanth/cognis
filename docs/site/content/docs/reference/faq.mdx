<Accordions>
  <Accordion title="Is Cognis production-ready?">
    Cognis is pre-1.0 (currently `0.3.x`). The core traits (`Runnable`, `Tool`,
    `Memory`, `Graph<S>`) are stable in shape and used across the whole
    workspace, but the public API can still change between minor versions
    until 1.0. Several teams run it in production today against Ollama and
    OpenAI; see [Going to production](/docs/production/going-to-production) for
    the hardening checklist (retries, rate limits, observability) before you
    ship.
  </Accordion>

  <Accordion title="Why Rust instead of Python for LLM apps?">
    Because the parts of an agent that aren't the model call — tool dispatch,
    message history, graph state, retry/fallback logic — benefit from a type
    system that catches mistakes before you run anything. A `Runnable<I, O>`
    carries real types end-to-end, so a mismatched pipe is a compile error,
    not a runtime `KeyError` three calls deep. See [Why Rust](/docs/introduction#why-rust)
    for the full case, and [Core ideas → Runnables](/docs/core-ideas/runnables)
    for how that plays out in practice.
  </Accordion>

  <Accordion title="How is Cognis different from other Rust LLM frameworks?">
    Most Rust LLM libraries stop at "unified client across providers plus
    tool calling." Cognis adds two things most don't have at all: a
    **stateful graph engine** (`cognis-graph` — Pregel-style supersteps,
    per-field reducers, checkpointing, time-travel) and a **production
    middleware stack** (retry, fallback, rate limiting, PII redaction, prompt
    caching, planning, summarization) that ships as composable wrappers
    rather than something you hand-roll per project. See
    [Patterns](/docs/patterns/research-assistant) for worked examples that lean on
    both.
  </Accordion>

  <Accordion title="Do I need to enable every feature flag?">
    No — everything outside `cognis-core` is feature-gated and opt-in.
    `cognis = { version = "0.3", features = ["ollama"] }` compiles in only the
    Ollama provider; your binary won't carry OpenAI, vector-store, or
    checkpointer code you never call. See
    [Feature flags](/docs/reference/feature-flags) for the full list.
  </Accordion>

  <Accordion title="Can I use Cognis without tokio?">
    Not directly — I/O-bound trait methods (`Runnable::invoke`,
    `Tool::_run`, provider calls) are `async` via `#[async_trait]` and the
    workspace is built on the `tokio` runtime throughout. There's no sync
    wrapper shipped; if you need a sync call site, use
    `tokio::runtime::Handle::block_on` at your boundary.
  </Accordion>

  <Accordion title="Which LLM providers and vector stores are supported?">
    Six providers behind one `Client`: OpenAI, Anthropic, Google, Ollama,
    Azure, and OpenRouter (which reuses the OpenAI wire format). Six vector
    store backends behind one trait: in-memory, FAISS, Chroma, Qdrant,
    Pinecone, and Weaviate. See
    [Building agents → Models](/docs/building-agents/models/overview) and
    [Building RAG → Vector stores](/docs/building-rag/vector-stores/overview).
  </Accordion>

  <Accordion title="What's missing today?">
    Being upfront about the gaps so you can decide whether to wait or
    contribute:
    - **LangSmith and OpenTelemetry exporters** — [Langfuse](/docs/observability/langfuse)
      is the supported production tracing backend today. The
      `TraceExporter` trait is one async method, so building your own
      bridge is fast.
    - **A hosted gateway or managed deployment** — bring your own infra.
      Production *patterns* are documented; a managed runtime isn't
      shipping.
    - **A wider provider matrix** — six are battle-tested; others (Groq,
      Together, Bedrock direct, Cohere) are open issues looking for owners.

    See the [full roadmap on GitHub](https://github.com/0xvasanth/cognis/issues).
  </Accordion>

  <Accordion title="What license is Cognis under?">
    MIT. See the [LICENSE](https://github.com/0xvasanth/cognis/blob/main/LICENSE)
    file in the repo.
  </Accordion>

  <Accordion title="How do I report a bug or request a feature?">
    Open an issue on [GitHub](https://github.com/0xvasanth/cognis/issues). If
    it's a build or compile error, include a minimal `main.rs` and the
    `Cargo.toml` features you enabled — see
    [Troubleshooting](/docs/reference/troubleshooting) first in case it's a known
    sharp edge.
  </Accordion>

  <Accordion title="How do I contribute?">
    Start at [Ways to contribute](/docs/contribute/ways-to-contribute) — it covers
    adding a provider, a vector store, or a tool, plus the development setup
    and pull request process.
  </Accordion>
