Both variants buffer messages like `Buffer` does, but also run an extractor over every written message and surface the extracted facts as a system-message preamble on `seed()` — so the model sees a running ledger of what it's learned, not just raw transcript.

<Callout type="warn">
Both variants' `seed()` prepends a synthesized preamble ("Known entities:" / "Knowledge:"). `seed().len() == read().len()` is **not** a safe assumption for either — see [Troubleshooting](/docs/reference/troubleshooting#entitymemory-knowledgegraphmemory-return-more-messages-than-i-wrote).
</Callout>

## EntityMemory — track entities across turns

```rust
use cognis::prelude::*;

let memory = EntityMemory::new()
    .with_system("You are a helpful assistant.");
```

Default extractor is a capitalized-word heuristic: any token starting with an uppercase letter becomes an entity, paired with the sentence it appeared in as the fact. Good enough to bootstrap with, but crude — plug in your own for anything production-grade:

```rust
use std::sync::Arc;
use cognis::agent::memory::{EntityFact, EntityMemory};

let memory = EntityMemory::new().with_extractor(Arc::new(|text: &str| -> Vec<EntityFact> {
    // call an LLM, a NER model, a regex — anything returning (entity, fact) pairs
    extract_entities_via_llm(text)
}));
```

`seed()` surfaces the accumulated ledger as a system-message preamble, so the model can reference "Maya mentioned she works at Acme" three turns later without it being in the raw window.

## KnowledgeGraphMemory — reason over relationships

```rust
use cognis::prelude::*;

let memory = KnowledgeGraphMemory::new()
    .with_system("You are a research assistant.");
```

Same shape as `EntityMemory`, but extracts subject-predicate-object triples instead of entity/fact pairs. The default extractor handles simple "X is Y" / "X has Y" / "X are Y" patterns — genuinely useful for a demo, not for production. Swap in an LLM-driven extractor the same way:

```rust
use std::sync::Arc;
use cognis::agent::memory::{Triple, KnowledgeGraphMemory};

let memory = KnowledgeGraphMemory::new().with_extractor(Arc::new(|text: &str| -> Vec<Triple> {
    extract_triples_via_llm(text)  // Vec<(subject, predicate, object)>
}));
```

`seed()` prefixes a `Knowledge:` system message listing every triple collected so far — the model reasons over accumulated relationships (`Maya — works_at — Acme`, `Acme — located_in — Berlin`) rather than re-deriving them from scratch each turn.

## Choosing between the two

Reach for `EntityMemory` when you mainly need "what has the user told me about X" recall. Reach for `KnowledgeGraphMemory` when the agent needs to reason over relationships between things, not just facts about one thing at a time — the triple shape is what makes multi-hop reasoning ("where does the company Maya works at keep its headquarters?") possible.
