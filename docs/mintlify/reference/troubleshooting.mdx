These are real gotchas, not hypotheticals — each one has tripped someone up while building against Cognis. Find the symptom, apply the fix.

## `#[tool]` macro fails to find the `Tool` trait

**Symptom:** A struct annotated with `#[tool]` fails to compile with an error that it doesn't implement `Tool`, or that `cognis_core::Tool` doesn't exist.

**Cause:** The macro defaults `crate_path = "cognis_core"`, but the runtime `Tool` trait now lives in `cognis_llm::tools`. The macro hasn't been reconciled with that move yet.

**Fix:** For now, write the `impl Tool` block by hand instead of using `#[tool]`:

```rust
use cognis_llm::tools::{Tool, ToolInput, ToolOutput};

struct Calculator;

#[async_trait::async_trait]
impl Tool for Calculator {
    fn name(&self) -> &str { "calculator" }
    fn description(&self) -> &str { "Evaluates an arithmetic expression." }
    // args_schema, _run ...
}
```

## `LinearBuilder` ignores my linear edges

**Symptom:** You built a pipeline with `LinearBuilder`, expecting stage `"0"` to flow into stage `"1"`, but execution jumps somewhere else or stops early.

**Cause:** `LinearBuilder` auto-names stages `"0"`, `"1"`, … and does wire up linear edges between them — but a node's returned `Goto` always overrides the linear edge. There's no fall-through once a node returns its own `Goto`.

**Fix:** Either return `Goto::node("<next-index>")` explicitly from every stage, or skip `LinearBuilder` and use `Graph::new()` with explicit edges when you need real conditional routing.

## `FuturesUnordered` won't compile with my spawned futures

**Symptom:** `error[E0308]: mismatched types` when pushing futures into a `FuturesUnordered`, usually something about "opaque type" or every `async move` block having a distinct type.

**Cause:** `FuturesUnordered` requires a single concrete future type. Two `async move { ... }` blocks are never the same type, even if they return the same thing.

**Fix:** Box and pin each one, and type the collection as `BoxFuture`:

```rust
use futures::future::BoxFuture;
use futures::stream::FuturesUnordered;

let mut futs: FuturesUnordered<BoxFuture<'static, Result<Output>>> = FuturesUnordered::new();
futs.push(Box::pin(async move { /* ... */ }));
```

## Workspace won't build after adding `cognis-graph` as a path dependency

**Symptom:** `cargo build` fails to resolve a dependency even though the directory clearly exists at `crates/cognisgraph`.

**Cause:** The directory name and the crate name don't match. The folder is `crates/cognisgraph`, but the crate's `name` in its `Cargo.toml` is `cognis-graph`. Workspace `[workspace.dependencies]` entries key on the **crate name**, not the directory.

**Fix:**

```toml
# Cargo.toml — correct
cognis-graph = { path = "crates/cognisgraph", version = "0.3" }
```

## `EntityMemory` / `KnowledgeGraphMemory` return more messages than I wrote

**Symptom:** You called `memory.write(...)` three times, but `memory.read(...)` or the preamble passed to the model is longer than you expect — there's an extra system-ish message at the front you didn't add.

**Cause:** Both `EntityMemory` and `KnowledgeGraphMemory` synthesize a preamble in `seed()` — a "Known entities:" or "Knowledge:" message — and prepend it. `seed().len() == read().len()` is **not** a safe assumption for these two memory variants.

**Fix:** If you need the raw turns without the synthesized preamble, call `read()` directly rather than `seed()`, or account for the extra leading message when asserting on history length in tests.

## The umbrella `cognis` crate won't compile after I added a new error variant

**Symptom:** A new error type in the `cognis` crate fails to compile with missing trait impls for `Display` or `std::error::Error`, even though every sub-crate uses `thiserror` fine.

**Cause:** `cognis` deliberately does **not** depend on `thiserror` directly — it's the one crate that sits above all four siblings, and pulling in another proc-macro dependency there wasn't worth it.

**Fix:** Hand-roll the impls:

```rust
#[derive(Debug)]
pub enum SubscribeError { Closed, Lagged(u64), Empty }

impl std::fmt::Display for SubscribeError {
    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
        match self {
            Self::Closed => write!(f, "channel closed"),
            Self::Lagged(n) => write!(f, "lagged by {n} messages"),
            Self::Empty => write!(f, "no messages available"),
        }
    }
}

impl std::error::Error for SubscribeError {}
```

## Still stuck?

Open a [GitHub issue](https://github.com/0xvasanth/cognis/issues) with a minimal repro — a single `main.rs` and the `Cargo.toml` features you enabled reproduces most of these faster than a description alone.
