Backed by any `VectorStore` from [Building RAG → Vector stores](/building-rag/vector-stores/overview). Every `write()` embeds the message text and adds it to the store, tagged with role metadata.

## Construct

```rust
use std::sync::Arc;
use tokio::sync::RwLock;
use cognis::prelude::*;
use cognis_rag::vectorstore::InMemoryVectorStore;

let store = Arc::new(RwLock::new(InMemoryVectorStore::new(embedder)));
let memory = VectorMemory::new(store)
    .with_k(5)                                   // top-5 recall, default varies — set explicitly
    .with_system("You are a long-term personal assistant.");
```

## The recall model is different from every other variant

`seed()` on a `VectorMemory` returns **only the pinned system message** — not the full history, not a window, not a summary. Semantic recall is opt-in and explicit:

```rust
let relevant: Vec<Message> = memory.recall("what did we decide about the budget?").await?;
```

Call `.recall(query)` yourself — typically with the user's current message as the query — and splice the results into your prompt however fits your application. This is the one memory variant that doesn't automatically shape what the agent sees on every turn; it's built for long-term knowledge you pull in on demand, not a running conversational window.

## When to use it

Reach for `VectorMemory` when the thing you need isn't "the last N turns" but "whatever's relevant to *this* question, out of everything ever said" — a long-running assistant across weeks of conversation, or an agent that needs to recall a fact mentioned once, months of messages ago, that a `Window` or `SummaryBufferMemory` would have long since dropped or compressed away.
