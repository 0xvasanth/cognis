Feature flag: `anthropic`. Default base URL: `https://api.anthropic.com/v1/`. Default `anthropic-version` header: `2023-06-01`.

## Construct

```rust
use cognis_llm::provider::anthropic::AnthropicBuilder;

let provider = AnthropicBuilder::default()
    .api_key(std::env::var("ANTHROPIC_API_KEY")?)
    .model("claude-sonnet-4")
    .anthropic_version("2023-06-01")  // optional override
    .build()?;
```

Or via env: `COGNIS_PROVIDER=anthropic`, `COGNIS_ANTHROPIC_API_KEY`, `COGNIS_ANTHROPIC_MODEL`.

## Builder methods

| Method | Notes |
|---|---|
| `api_key(key)` | Required. |
| `model(name)` | Required — no default. |
| `base_url(url)` | Override the API base. |
| `anthropic_version(v)` | Override the required `anthropic-version` header. |
| `extra_header(k, v)` | Add arbitrary headers. |
| `timeout_secs(s)` | Per-request timeout. |

## Wire format notes — different enough from OpenAI to matter

- **No `system` role.** The system prompt is a top-level request field, not a message in the array. Cognis handles this translation for you, but it matters if you're debugging raw requests.
- **Tool use is content blocks**, not a separate `tool_calls` field — `tool_use` / `tool_result` blocks inside the message content. Normalized to the same `ToolCall` type as every other provider on the Cognis side.
- **Auth is `x-api-key`**, plus the required `anthropic-version` header — not `Authorization: Bearer`.
- **Streaming is named SSE events** (`content_block_delta`, etc.), not the `[DONE]` sentinel OpenAI uses.
