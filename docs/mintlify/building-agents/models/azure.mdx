Feature flag: `azure`. Default `api-version`: `2024-08-01-preview`.

## Construct

```rust
use cognis_llm::provider::azure::AzureBuilder;

let provider = AzureBuilder::default()
    .endpoint(std::env::var("AZURE_OPENAI_ENDPOINT")?)  // https://your-resource.openai.azure.com/
    .deployment("gpt-4o-prod")
    .api_version("2024-08-06")
    .api_key(std::env::var("AZURE_OPENAI_API_KEY")?)
    .build()?;
```

Or via env: `COGNIS_PROVIDER=azure`, `COGNIS_AZURE_API_KEY`, `COGNIS_AZURE_ENDPOINT`, `COGNIS_AZURE_DEPLOYMENT`, `COGNIS_AZURE_API_VERSION` — see [Environment variables → Azure-specific](/reference/env-vars#azure-specific).

## Builder methods

| Method | Notes |
|---|---|
| `endpoint(url)` | Required. Your Azure resource URL. |
| `deployment(name)` | Required. Your custom deployment alias — **this is what selects the model**, not a model name. |
| `api_key(key)` | Required. |
| `api_version(v)` | Defaults to `2024-08-01-preview`. |
| `extra_header(k, v)` | Add arbitrary headers. |
| `timeout_secs(s)` | Per-request timeout. |

## Wire format notes — the part that trips people up

- **The wire format is identical to OpenAI's** chat completions API — same request/response shapes.
- **URLs are deployment-scoped:** `https://{resource}.openai.azure.com/openai/deployments/{deployment}/chat/completions?api-version=...`. The deployment name lives in the URL path, not a `model` field doing the real selection.
- **Auth is an `api-key` header**, not `Authorization: Bearer` — easy to copy-paste from OpenAI setup and get this wrong.
- `deployment` is sent in the request body too, for correlation — but the URL path is what Azure actually routes on.
